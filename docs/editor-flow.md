# 后台内容流程

## 唯一事实来源

- 编辑中的正文先写入当前浏览器；这是离开页面时的恢复副本，不代表云端已保存。
- 草稿同步成功由后台草稿接口返回版本号确认；编辑器才显示“已保存”。
- 提交文章成功由开发仓库返回提交记录确认；这不代表生产仓同步或网站上线。
- 上线状态必须来自部署结果与正式页面检查，不能由编辑器推断。

## 编辑器操作

| 状态 | 主操作 | 反馈与离开 |
| --- | --- | --- |
| 未修改或本机已存、云端待同步 | 保存草稿 | 提示云端未保存，先确认本机写入 |
| 本机或云端保存中 | 保存草稿（转圈、禁用） | 等待本机写入；云端未确认时提示 |
| 云端保存失败 | 保存草稿 | 页面显示原因；离开前提示，仅保留本机副本 |
| 云端已确认且无后续改动 | 保存草稿 | 短暂显示成功提示；可以直接离开 |
| 本机保存失败 | 保存草稿 | 页面显示原因；停留在编辑器 |

编辑器工具栏的按钮始终叫“保存草稿”，旁边显示简短状态；鼠标悬停可查看完整状态，保存中按钮显示转圈，失败在编辑区显示原因。草稿箱区分“仅本机”和“云端”，不把本机副本称为云端保存。

## 提交与上线

“提交文章”只写开发仓库。提交成功后，草稿从草稿箱移到仓库文章；页面展示提交记录。生产同步、构建和正式页面各自报告结果；没有核验数据时显示“待核验”，不称“已上线”。导航改动进入开发仓库审核分支，也不称“已发布”。

## 跨页面交互规则

- 所有编辑入口都使用同一套文章状态：草稿、已提交开发仓库、生产同步中、已上线、失败。页面只显示有证据的状态。
- 保存和提交是不同操作。保存草稿不改仓库；提交文章不代表上线。导航的“提交审核”也不等于保存草稿或上线。
- 图床上传只确认图片对象存在；正文是否保存、提交或引用图片，需要分别检查。媒体库不把“未发现引用”解释成可删除。
- 离开写作页时先确认本机写入。云端未确认时明确询问是否只保留本机副本；本机写入失败则不离开。
- 工具栏保持写作操作；状态只在唯一的保存控件上表达。具体错误通过操作反馈展示，不重复堆在工具栏。
- 版本与恢复只展示已存在的仓库提交、发布版本和备份。恢复操作必须指明目标版本与影响范围，不能把“查看历史”误写成“已恢复”。
- 连接设置区分 Cloudflare Access 登录、GitHub App 仓库授权和图床授权。登录后台本身不扩大其他服务权限。
